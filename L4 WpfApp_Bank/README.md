
# L4 WpfApp_Bank — Мини-банк

**Пятый, финальный шаг** в базовом блоке изучения WPF перед переходом к MVVM. Это небольшое, но полноценное приложение объединяет все ключевые концепции, изученные в предыдущих проектах: разметку, элементы управления, привязку данных, коллекции, события, валидацию и работу с данными.

## 🎯 Цель проекта

1.  **Закрепить** все изученные темы WPF в одном практическом задании.
2.  **Показать**, как создается полноценное приложение с бизнес-логикой и историей операций.
3.  **Выявить** ограничения текущего подхода (Code-behind) и подготовить почву для изучения паттерна **MVVM**, который решает эти проблемы.

## 💰 Бизнес-логика приложения

Приложение реализует простые, но важные правила:

| Функция | Описание | Валидация |
| :--- | :--- | :--- |
| **Пополнение баланса** | Внесение суммы на счет. | Сумма должна быть больше нуля. |
| **Снятие денег** | Списание суммы со счета. | Сумма должна быть больше нуля **и** не превышать текущий баланс. |
| **История операций** | Каждое действие (пополнение/снятие) сохраняется в `ListBox`. | Автоматически добавляется при успешной операции. |
| **Обновление баланса** | Отображается в интерфейсе. | В текущей версии обновляется вручную (`UpdateBalance()`). |

## 📝 Пример кода и важные нюансы

### 1. Основной класс счета (`BankAccount.cs`)

```csharp
public class BankAccount
{
    private decimal _balance;

    public decimal Balance => _balance;

    public BankAccount(decimal initialBalance = 0)
    {
        _balance = initialBalance;
    }

    public bool Deposit(decimal amount)
    {
        if (amount <= 0) return false;
        _balance += amount;
        return true;
    }

    public bool Withdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance) return false;
        _balance -= amount;
        return true;
    }
}
```

### 2. Модель операции (`BankOperation.cs`)

```csharp
public class BankOperation
{
    public string Type { get; }      // "Пополнение" или "Снятие"
    public decimal Amount { get; }
    public DateTime Date { get; }

    public BankOperation(string type, decimal amount)
    {
        Type = type;
        Amount = amount;
        Date = DateTime.Now;
    }

    public override string ToString()
    {
        return $"{Date:dd.MM.yyyy HH:mm} - {Type}: {Amount:N2} ₽";
    }
}
```

### 3. Работа с историей и Binding (XAML)

```xml
<!-- Привязка истории к ListBox -->
<ListBox ItemsSource="{Binding Operations}" />

<!-- DataTemplate для отображения операции -->
<DataTemplate>
    <TextBlock Text="{Binding}" Foreground="Blue" />
</DataTemplate>
```

### 4. Почему баланс обновляется вручную?

В текущей версии приложения (без MVVM) используется `ObservableCollection<T>` для истории операций, которая автоматически обновляет UI при добавлении новых элементов. Однако свойство `Balance` в классе `BankAccount` **не уведомляет** интерфейс об изменении своего значения.

Поэтому в обработчиках событий приходится вызывать метод `UpdateBalance()` вручную:

```csharp
private void UpdateBalance()
{
    BalanceTextBlock.Text = $"{_account.Balance:N2} ₽";
}
```

#### Решение (в следующем шаге)

Чтобы избавиться от ручного обновления, необходимо реализовать интерфейс **`INotifyPropertyChanged`**:

```csharp
public class BankAccount : INotifyPropertyChanged
{
    private decimal _balance;
    public event PropertyChangedEventHandler? PropertyChanged;

    public decimal Balance
    {
        get => _balance;
        private set
        {
            if (_balance != value)
            {
                _balance = value;
                OnPropertyChanged(nameof(Balance));
            }
        }
    }

    protected void OnPropertyChanged(string propertyName) =>
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
}
```

Теперь при изменении баланса UI обновится автоматически, а код `UpdateBalance()` станет не нужен.

## 💡 Ключевые выводы перед переходом к MVVM

1.  **Мы объединили все изученные темы:** XAML, элементы управления, Binding, коллекции, события и валидацию.
2.  **Мы увидели ограничения Code-behind:** логика обновления UI смешана с бизнес-логикой, код становится сложнее с ростом приложения.
3.  **`INotifyPropertyChanged`** — это следующий важный шаг, который сделает приложение более реактивным.
4.  **MVVM** решает эти проблемы, позволяя полностью отделить интерфейс (View) от логики (ViewModel) и сделать код более чистым, тестируемым и поддерживаемым.
